## 젠슨↔헤르메스 상호보완·디벨롭 체계 (JH-Loop v1) — 2026-09-05 부빠 지시

> 부빠 지시: 양측이 서로 분석 공유하고 상호보완점 기반으로 더 디벨롭하는 체계 구축. 젠슨=lead/synthesizer.
> 엔진 프로파일: 젠슨=Opus 4.8(심층추론·수치정합·검증·감수, 느림·고비용). 헤르메스=step-3.7-flash:free(속도·처리량·무료, 정밀검증 약함). 벤치 98 vs 80.

**1. 역할 라우팅 (task→engine)**
- 헤르메스 선행: 1차 초안·대량 반복(데이터수집·엣지케이스·스캐폴딩)·빠른 응답/모니터링.
- 젠슨 마무리: 설계·수치정합·엔진 정확성·최종 감수·단일안 보고.
- 기준: 정확성 치명적 → 젠슨 마무리 / 물량·속도 → 헤르메스 선행.

**2. 교차검증 프로토콜 (골든셋)**
- 무한매수 공동구축서 검증된 패턴 재사용: 양쪽 독립 산출 → 공통 assert(골든셋) 숫자 일치 확인 → 불일치 시 3층 원인규명(평가방식·계측버그·파라미터).
- 정량 산출물은 골든셋 통과 후에만 보고.

**3. 논의 매개**
- 공유 볼트 보드(openclaw.md↔elon-musk.md)에 각자 분석·이견 기록 → 젠슨 수렴 → 단일안. 30분 푸시 크론+필요시 즉시.

**4. 지속개선 루프 (miss→rule)**
- 헤르메스 산출물서 걸러낸 오류(사양위반·사실오류)는 개별지적에 그치지 않고 재발방지 규칙으로 메모리 축적(verification-ownership 등).
- 젠슨 약점(느림·장황·턴끊김)은 헤르메스 선행·턴분할로 보완.
- 정기 벤치 재측정(현 98/80)으로 격차·개선 추적.

**5. 에스컬레이션·한도**
- 헤르메스 무료모델 rate-limit/한도 신호 → 조기 인계(버퍼). 엔진 업그레이드(Sonnet5 이식 실패 이력)는 quota구조 확인 후 부빠 승인.
